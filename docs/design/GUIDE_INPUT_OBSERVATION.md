# 장전 가이드 입력 근거 연결 순서

## 현재 구현

- `PremarketGuideInputAudit`는 가이드별 제공자, 기록 시각, 미검증 사유를 보존한다. 전체 입력을 대표하는 단일 수신 시각과 입력 해시는 아직 비워 둔다. 개별 캔들 HTTP 응답 수신 시각은 아래의 자산별 근거에 별도로 보존한다.
- `CompletedWeeklyCandleCache`는 최초 로드가 애플리케이션에서 끝난 시각을 캔들과 함께 보존한다. 캐시 적중 시 시각을 새로 만들지 않는다. 이 시각은 거래소의 공표 시각이나 제공자 원본 응답 시각이 아니다.
- 토스증권 캔들 캐시는 포트폴리오별로 분리한다. 공개 시세 제공자 캐시는 포트폴리오 간 공유하되, 자산별 근거는 해당 가이드 스냅샷에 별도로 저장한다.
- 토스 일봉 페이지가 겹치면 날짜별로 한 건만 남긴다. 같은 날짜의 OHLCV가 충돌하거나 페이지 커서·날짜가 진행하지 않으면 조회 실패로 처리해 주봉 거래량과 근거 해시가 잘못 계산되지 않게 한다. 이 검증은 원본 수신 시각의 보존을 대신하지 않는다.
- `PremarketGuideService`는 실제 가이드에 포함된 자산에 대해 캐시의 **완료된 주봉** 기준일이 가이드의 기준일과 일치할 때만 `premarket_guide_candle_evidence`에 제공자·로드 완료 시각·캔들 수·SHA-256을 저장한다. 강제 재생성 시 같은 자산의 근거를 갱신하고 사라진 자산은 제거한다.
- `candle_sha256`은 `MarketCandleDigest` 직렬화 형식 **v2**(2026-09-23)로 계산한다. 가격을 표기가 아니라 값으로 직렬화(`stripTrailingZeros().toPlainString()`)하므로 `100`과 `100.0`은 같은 해시다. 토스 일봉 중복 검사(`compareTo`)와 같은 "같은 값" 기준이다. 이 변경 전에 저장된 행은 v1(표기 기준)이며 v2 해시와 비교할 수 없다. 형식 버전은 DB 컬럼으로 저장하지 않는다. 해시를 검증하는 기능을 만들 때 버전 컬럼 추가를 함께 결정한다.
- 토스 캔들 응답은 각 HTTP 페이지의 본문 수신 완료 시각을 별도 목록으로 보존한다. Twelve Data는 단일 HTTP 응답의 수신 완료 시각을 보존한다. 가이드 종목의 근거에 수신 순서대로 저장되며 캐시 적중 시 새 시각을 만들지 않는다. 토스의 `adjusted_requested=true`는 요청의 `adjusted=true` 파라미터를 뜻할 뿐, 제공자 가격이 실제로 어떤 기업행위로 조정됐는지를 검증한 결과가 아니다. Twelve Data는 조정 여부를 명시적으로 요청하지 않으므로 `adjusted_requested`가 비어 있다. 기존 스냅샷과 관측을 지원하지 않는 제공자의 수신 근거도 비어 있다.
- 포트폴리오 결정 입력(원장·보유·트랙 재정의·손절 설정·후보군·전역 카탈로그·증권사 보유 스냅샷 참조)은 가이드 생성 시작 시 한 번 읽어 보유·후보 배치가 공유하고, 구성요소별 다이제스트를 `premarket_guide_portfolio_states`(V34)에 저장한다. 저장 직전 재대조가 일치하면 감사 기록의 `portfolio_state_ref`를 채우고 `PORTFOLIO_STATE_NOT_CAPTURED`를 빼며, 다르면 `PORTFOLIO_STATE_CHANGED_DURING_GENERATION`을 남긴다. 상세: `docs/design/PORTFOLIO_STATE_SNAPSHOT_PROPOSAL.md` 8절.
- 자산별 캔들 근거와 포트폴리오 상태는 전체 가이드 입력의 일부다. 공급자 조정 정책은 아직 고정되지 않았으므로 `PremarketGuideInputAudit.inputSha256`은 비어 있고 UI의 `입력 근거 미검증` 상태도 유지한다.
- 가이드에 포함된 종목의 캔들 근거가 누락되거나 기준일·제공자가 일치하지 않으면 감사 기록의 `missing_reasons`에 `CANDLE_EVIDENCE_INCOMPLETE`를 추가한다. 강제 재생성 시 이전 근거가 새 가이드에 남지 않는지도 검증한다. 이 사유가 없더라도 전체 입력이 검증된 것은 아니다.

## 다음 연결 단위

1. 공급자별 실제 가격 조정 정책과 기업행위 반영 여부를 별도 계보로 검증한다. 현재는 HTTP 수신 완료 시각과 토스의 조정 요청값까지만 연결됐다.
2. 보유 원장 버전·후보/위험 설정 버전을 함께 고정한 뒤 가이드 전체 입력 해시를 산출한다. 일부만 있으면 전체 입력 해시를 기록하지 않는다.
3. 부분 실패, 제공자 변경, 회원·포트폴리오 격리, 과거 가이드 재생 테스트를 통과한 뒤에만 감사 상태를 상향한다. 수익성 검증과 주문 가능성 검증은 별도다.

자산별 로드 완료 시각을 기존 감사 테이블의 `response_received_at`에 그대로 복사하지 않는다. 여러 자산과 캐시가 섞일 때 단일 시각은 입력 전체의 계보를 설명하지 못한다.

### 2026-09-23 검증 상태

- Toss 일봉 이력 끝의 부분 페이지와 `nextBefore=null` 동작은 US 3종목·KR 3종목에서 관측했고 회귀 테스트(`ac4e98f`)를 추가했다. 커서가 반복되거나 날짜가 진행하지 않는 경우의 실패 처리(`41ec765`)는 유지한다.
- 캔들 해시는 가격 표기 차이를 정규화한 v2(`f36f1b6`)다. 이전 저장 행은 v1이므로 버전 구분 없이 두 해시를 동일 근거로 비교하지 않는다.
- V31~V33의 PostgreSQL 통합 테스트 37개가 통과했고, 근거 저장·조회와 재생성 시 삭제 순서까지 왕복 검증했다(`334711d`). Claude가 보고한 백엔드 전체 테스트 결과는 1,113개 통과·3개 건너뜀이다. 이 수치는 해당 검증 시점의 결과이며 이후 변경의 자동 보증은 아니다.
- Toss 일봉 세션 범위는 2026-09-23 1차 관측만 완료했다. 최신 일봉에 장전 거래가 섞이는지는 가설이며 2026-09-24 05:00 KST 이후의 2차 관측 전에는 확정하거나 보정 코드를 넣지 않는다.
- 보유 원장·후보군·위험 설정은 C-2(V34)로 한 시점의 스냅샷 다이제스트에 묶였다. 생성 중 원장 커밋 시 종목이 보유·후보 어디에도 나오지 않던 결함은 PostgreSQL 통합 테스트로 재현 후 해소했다. 전체 입력 해시와 검증 상태는 여전히 미완성이며 수익성·주문 적합성도 입증되지 않았다.
