# Track A 후보 가이드 UX 정비

## 목표

전략 가이드의 후보 영역이 투자 추천이나 전 종목 스크리닝으로 오해되지 않도록, 현재 구현된 `TRACK_A` 후보 가이드의 대상·신호·제한을 사용자가 이해할 수 있게 정비한다.

## 현재 계약

- 후보 API는 관리자가 `TRACK_A`로 등록한 `AssetProfile` 가운데 현재 포트폴리오에 없는 종목만 조회한다.
- 각 후보에는 완료 주봉 10주/40주 이동평균 기반 신호를 계산한다.
- 이는 자동 주문 또는 개인화된 투자 적합성 판단이 아니다.
- 요청 제한 또는 데이터 불가 종목은 기존 부분 실패 응답을 그대로 표시해야 한다.

## 변경 범위

- `frontend/src/pages/StrategyGuidesPage.tsx`
- 후보 영역에 직접 사용하는 `frontend/src/components/strategy/**`
- 필요한 스타일은 `frontend/src/App.css`
- 관련 프론트엔드 테스트가 이미 있으면 해당 범위만 수정 가능

## 하지 말 것

- 백엔드 API, 데이터 모델, 마이그레이션을 바꾸지 않는다.
- 후보 종목을 매수 추천, 적합성 판단, 수익 보장처럼 표현하지 않는다.
- Track B를 선택·표시 가능한 실행 전략으로 만들지 않는다.
- 다른 페이지를 리팩터링하지 않는다.

## 수용 기준

1. 후보 가이드의 기준이 `관리자가 등록한 Track A 대상군`이라는 점이 화면에서 이해된다.
2. `완료 주봉 10/40 이동평균 신호`이며 자동 주문이 아니라 검토용 정보임을 짧고 자연스러운 한국어로 표시한다.
3. 후보 없음, 데이터 일부 불가, 요청 제한 상태의 기존 동작을 훼손하지 않는다.
4. 데스크톱과 360px 폭에서 제목·안내·버튼·목록이 잘리지 않으며 수평 스크롤이 생기지 않는다.
5. lint, TypeScript 검사, production build를 실행하고 결과를 보고한다.
