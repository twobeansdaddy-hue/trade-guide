# Track B 횡단면 모멘텀 검증 설계

## 목표

Track B를 구현하거나 화면에 노출하지 말고, 횡단면 모멘텀 후보를 재현 가능하게 검증하기 위한 백테스트 설계와 최소한의 순수 계산 코어를 만든다.

## 배경

- Track A는 개별 종목의 완료 주봉 10/40 이동평균 교차를 쓰는 시계열 추세 전략이다.
- Track B 후보는 동일 유니버스 내 상대강도를 사용하는 횡단면 모멘텀이다.
- 이전 조사에서 후보는 `직전 52주 수익률에서 최근 4주를 제외한 48주 수익률`, 분기 리밸런싱, 상위 후보군, 비용·슬리피지 반영으로 제안됐지만 아직 채택되지 않았다.
- 현재 Track B는 API 및 사용자 UI에서 선택 불가이며, 이 상태를 유지해야 한다.

## 변경 범위

- `src/main/java/com/tradeguide/service/backtest/**`
- `src/main/java/com/tradeguide/domain/backtest/**`
- `src/test/java/com/tradeguide/service/backtest/**`
- `research/reports/**`
- 필요 시 테스트 전용 고정 데이터는 `src/test/resources/**`

## 구현 원칙

1. 외부 API 호출, 데이터베이스 쓰기, HTTP API, 화면 변경, 주문 생성은 금지한다.
2. 입력은 시점 순서가 보장된 종목별 완료 주봉 가격 이력이어야 한다.
3. 52주 형성기간에서 최근 4주를 제외하는 상대수익률 산식, 리밸런싱 시점, 상위 후보 선택, 동일가중 포트폴리오 수익 계산을 순수 계산 코드로 분리한다.
4. 거래비용과 슬리피지는 호출자가 명시적으로 주입하는 가정값으로 둔다. 0 비용을 기본값으로 숨기지 않는다.
5. 생존 편향을 코드로 해결한 것처럼 주장하지 말고, 입력 유니버스가 point-in-time 구성인지 여부를 결과 메타데이터 또는 보고서에서 명확히 제한한다.
6. 이 작업은 검증 인프라다. `TradingStrategy`, `InvestmentTrack`, `StrategySelector`, Track B API, 데이터베이스, 프론트엔드를 수정하지 않는다.

## 테스트 수용 기준

- 고정된 작은 캔들 fixture로 최근 4주 제외 수익률과 순위가 정확함을 검증한다.
- 리밸런싱 이전에는 구성 종목이 바뀌지 않음을 검증한다.
- 비용이 있는 결과가 동일 조건의 무비용 결과보다 높지 않음을 검증한다.
- 미래 시점 가격이 과거 리밸런싱 순위에 영향을 주지 않음을 검증한다.
- 잘못된 이력 길이, 중복 날짜, 누락 종목 데이터는 명확히 거부하거나 결과에서 제외하는 정책을 테스트로 고정한다.
- Gradle 관련 테스트를 실행한다.
