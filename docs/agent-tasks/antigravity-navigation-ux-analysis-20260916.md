## Outcome

1. "각 메뉴별로 기능들이 다 포함되어 있다 보니 보기가 어렵다" — 화면당 정보/기능 밀도가
   높다는 지적.
2. "화면 사이즈별 반응형 UI는 잘 구현되어 있으나 LNB/GNB는 고정되어 있어야 이동하기
   편하지 않은가? (현재 웹 기획 트렌드 기준 검토 필요)" — 상단/좌측 내비게이션을
   스크롤에 따라 고정(sticky)할지 여부.

이 작업은 **구현하지 않는다**. 현재 구조를 분석하고, 실행 가능한 개선안을 근거와 함께
제안하는 짧은 보고서를 만든다. 사용자가 보고서를 보고 범위를 확정하면 그때 별도
구현 작업 계약을 만든다.

## 분석 결과

### 1. 현재 내비게이션 구조 현황
* **데스크톱 (768px 초과)**: GNB(`.topbar`)는 상단에 일반 스크롤(`static`)로 배치되어 있고, LNB(`.sidebar`)는 좌측에 `position: sticky; top: 0; max-height: 100vh; overflow-y: auto;`가 적용되어 스크롤 시에도 고정되어 있습니다.
* **모바일 (768px 이하)**: 좌측 LNB가 `position: static`으로 풀리며 상단 GNB 밑에 탭 형태(`grid-template-columns: repeat(3, minmax(0, 1fr))`)로 붙습니다. 모바일에서는 GNB와 LNB 모두 고정되지 않고 스크롤과 함께 올라갑니다.
* **스크롤 길이**: 총 6개 주요 메뉴 중 "전략 가이드"와 "연동 계좌(설정)" 화면은 섹션이 4~5개 이상 수직으로 나열되어 있어, 모바일이나 세로 해상도가 낮은 환경에서 스크롤 길이가 상당히 깁니다.

### 2. 메뉴 복잡도 현황
* **밀집도 높은 화면**:
  * **전략 가이드**: '오늘 장전 가이드', '매매 계획 초안(후보/보유)', '전략 가이드 상세(후보/보유)' 등 5개 이상의 섹션이 한 페이지에 연속으로 노출됩니다.
  * **설정/연동 계좌**: '증권사 계좌 연동', '위험 한도(손절률/비중) 설정', '시장 데이터 제공자', '종목별 전략 프로필 설정' 등 무거운 입력 폼과 리스트가 한 화면에 모여 있습니다.
* **정보 밀도 감소 제안**:
  1. **Sub-Tab 분리 (라우팅 기반 탭)**: 한 페이지 안에서 세부 탭을 나누어 보여줍니다. (예: 전략 가이드 화면을 '장전 요약 / 보유 / 후보' 탭으로 분할). 
     * *장단점*: 페이지가 매우 짧고 명확해지나, 현재 `#risk-policy`, `#held-asset-strategy-profiles` 등 앵커 링크로 화면 간 이동하는 로직이 탭 전환 로직과 충돌할 수 있어 구현 비용이 높습니다.
  2. **아코디언 (접기/펴기) 패턴**: 섹션 헤더에 요약 수치(총 N건)만 보여주고 기본적으로 닫아두는 방식입니다.
     * *장단점*: 기존 앵커 링크 구조를 해치지 않고 스크롤을 획기적으로 줄일 수 있으며 구현 비용이 낮습니다. 단점으로는 전체 항목을 스캐닝하려는 사용자에게 클릭 피로를 줄 수 있습니다.

### 3. GNB/LNB 고정(sticky) 여부 판단
* **데스크톱**: 현재 LNB가 이미 sticky이므로 메뉴 이동 편의성이 충족됩니다. GNB까지 고정하면 세로 공간 72px을 상시 점유하게 되므로 현행 유지를 권장합니다.
* **모바일 (375px)**: 현재 GNB(약 60px) + 2줄 LNB(약 76px)가 합쳐져 약 136px 높이를 가집니다. 이를 고정(sticky)할 경우, 작은 화면(예: 세로 667px 기준)의 약 20%를 내비게이션이 상시 차지하게 되어, 이 프로젝트의 핵심인 "종목 리스트와 가이드 텍스트 열람" 경험을 크게 해칩니다.
* **권장안 (Decision Needed)**:
  * 모바일 환경에서는 **현재처럼 비고정(static)을 유지**하거나, 트렌디한 조작감을 원할 경우 **스크롤 업 시에만 나타나는 헤더(Scroll-driven sticky)**를 도입하는 것을 권장합니다.
  * 복잡도가 높은 "전략 가이드"와 "연동 계좌" 화면은 탭 분리 대신 **아코디언 형태(접기/펴기)**로 섹션을 묶어 스크롤을 줄이는 방안을 가장 적은 비용의 개선안으로 제안합니다.
