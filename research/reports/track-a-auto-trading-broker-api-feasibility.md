# 오토매매 2단계 — 브로커 주문 실행 API 가능성 확인

- 날짜: 2026-09-17
- 배경: `research/TASKS.md` 9절 (D) "오토매매 전환 검토" 2단계 - 1단계
  (`track-a-real-cost-and-tax-revalidation.md`)가 세후로도 Track A 규칙의
  수익성을 확인한 뒤, 남은 핵심 블로커였던 "브로커가 개인용 주문 실행 API를
  제공하는가"를 확인한다. 이전 리서치(`track-c-kospi200-track-a-rule-validation.md`,
  2026-09-16)에서는 Toss API가 시세·주문이력 조회만 확인됐고 주문실행 API는
  조사하지 않았다고 명시했었다 - 이번에 그 공백을 메운다.
- 방법: 웹 검색 + 공식 문서(`developers.tossinvest.com`) 직접 확인. 이 리서치는
  실제로 API를 발급받거나 호출하지 않았다 - 문서·뉴스 기사 기반 확인이며,
  실제 발급·호출 테스트는 별도 작업이 필요하다는 것을 명시한다.

## 핵심 발견

**토스증권이 2026-08-13에 개인용 주문 실행 오픈API를 정식 출시했다.** 이전
리서치 시점(2026-09-16)에는 이 사실이 반영되지 않았었다 - 즉 지난 세션의
"Toss는 주문 실행 API가 없다(조사한 적 없다)"는 전제가 **최근 몇 주 사이에**
**바뀐 상태**였다.

| 항목 | 확인 내용 |
| --- | --- |
| 서비스 상태 | 2026-05 사전신청 시작(5.5만명 신청) → 2026-08-13 정식 서비스 개시 |
| 주문 기능 | 주문 생성·정정·취소·조회, 매수가능금액 조회, 매도가능수량 조회, 수수료 조회 |
| 시장 범위 | 국내(KRX)·미국 주식 모두 단일 API로 지원 |
| 인증 방식 | OAuth 2.0(Client Credentials), `client_id`/`client_secret`은 토스증권 PC웹(WTS) 로그인 후 "설정→Open API"에서 발급 |
| 발급 절차 | 공동인증서 불필요, 지문 승인 방식으로 비교적 간단 |
| 실시간 시세 | REST 폴링만 지원(웹소켓 미지원) - 초 단위 고빈도 전략에는 부적합, 분 단위 이상 봇에는 무관 |
| 수수료 | 기존 토스증권 계좌 요율과 동일 적용(국내 주식은 2026-06까지 한시 면제였다고 보도됨 - 지금은 종료됐을 가능성) |
| 자동매매 용도 | 언론 보도가 "새벽 자동매매"를 명시적 활용 사례로 소개 - 토스증권 스스로도 개인 자동매매 용도를 상정하고 있음을 시사 |

## Track A 규칙과의 적합성

Track A 프로덕션 규칙(10주/40주 SMA 골든크로스)은 **주봉 신호 기반**이라 리밸런싱
빈도가 매우 낮다(사이클당 진입 1회·청산 1회). REST 폴링만 지원한다는 제약은
이 규칙에는 전혀 문제가 되지 않는다 - 초 단위 반응이 필요한 전략이 아니기
때문이다. 국내·미국 주식을 단일 API로 지원한다는 점도 SOXL/TQQQ/TNA/FAS(미국
상장)와 향후 국내 레버리지 ETF(KODEX 레버리지 등) 양쪽에 같은 통합 경로로
접근할 수 있다는 뜻이라 유리하다.

## 대안 확인 — 한국투자증권(KIS) Open API

같은 검색에서 한국투자증권의 `open-trading-api`(GitHub, `koreainvestment/
open-trading-api`)도 확인됐다 - 이쪽은 훨씬 오래 전부터(수년 전) 개인 개발자용
주문 실행 API를 운영해 왔고, 웹소켓 실시간 시세를 지원하며 파생상품·해외주식·
채권까지 범위가 더 넓다. 다만 Toss와 달리 국내·해외가 API가 분리돼 있다고
알려져 있다(이번 리서치에서 상세 비교는 하지 않음). 사용자가 이미 Toss 계좌를
쓰고 있다는 점(`research/TASKS.md`가 언급한 "토스 국내(KRW) 주문 이력 원장 반영"
작업)을 고려하면 Toss API가 1순위 후보로 자연스럽다.

## 결론

**2단계 블로커는 해소됐다 - 개인이 실제로 신청·발급받아 주문을 실행할 수 있는**
**API가 (적어도 Toss 기준으로) 존재하고, 정식 서비스로 운영 중이다.** 오토매매
전환에 필요한 두 전제(1단계: 세후 수익성, 2단계: 주문실행 API 가능성) 모두
긍정적으로 확인됐다.

## Confidence와 caveats

**Confidence: medium** (공식 문서와 다수의 언론 보도로 서비스 존재 자체는
확인됐지만, 이 리서치는 실제로 API를 발급·호출해보지 않았다 - "문서상 가능"과
"실제로 안정적으로 동작"은 다를 수 있다).

- **실제 발급·호출 테스트를 하지 않았다** - `client_id`/`client_secret` 발급에는
  토스증권 계좌 로그인이 필요해 이 리서치 세션에서 직접 시도하지 않았다(계정
  자격증명이 필요한 작업이라 리서치 역할 범위를 벗어난다). 실제 신청 자격
  제한(예: 최소 예탁금, 계좌 개설 기간, 사업자 여부)이 있는지는 확인하지 못했다.
- 시장가/지정가 주문 유형별 상세 스펙, Rate limit(초당/분당 호출 제한), 주문
  실패 시 에러 코드 체계 등 실제 구현에 필요한 세부사항은 이번 조사 범위 밖이다
  - `developers.tossinvest.com/docs/order`가 JavaScript로 렌더링되는 SPA라
    WebFetch로 전체 내용을 가져오지 못했고, `llms.txt` 요약본으로 확인했다.
- 수수료 면제(2026-06까지)가 보도 시점 기준이라 지금(2026-09) 시점에 면제가
  종료됐을 가능성이 있다 - 실제 수수료율은 신청 시점에 재확인이 필요하다.
- 이 API의 **약관·서비스 안정성·장애 대응 정책**은 확인하지 않았다 - 실제
  자금이 걸린 자동 주문 시스템이라면 이 부분이 매우 중요하다.
- **법적/규제 확인 안 함**: 개인이 API로 자동매매를 하는 것 자체의 금융투자업
  관련 규제 준수 여부(예: 알고리즘 매매 신고 의무 등)는 이번 리서치에서 다루지
  않았다 - 실제 착수 전 확인이 필요하다.

## 다음 단계 제안

1. **3단계로 진행**: `CLAUDE.md`의 "자동 주문이나 수익 보장을 제공하지 않는다"
   원칙을 사용자별 opt-in 구조로 개정하는 논의, 그리고 권한/보안 아키텍처
   설계(자격증명 저장, 주문 감사로그, 서킷브레이커 등) - 이는 리서치가 아니라
   아키텍처 결정이라 별도 검토가 필요하다.
2. 실제 착수 전, Toss Open API를 실제로 발급받아 (a) 소액 모의/실주문으로
   API 동작 확인, (b) rate limit·에러 처리 세부사항 확인, (c) 알고리즘 매매
   관련 규제 준수 여부 확인 - 이 세 가지는 리서치가 아니라 사용자의 실제 계정
   작업이 필요하므로 사용자가 직접 진행하거나, 진행 후 결과를 공유하면 이어서
   설계에 반영할 수 있다.
