# Track B - 펀더멘털 데이터 제공자 도입 검토

> 이 문서는 연구/의사결정 지원 산출물이다. 어떤 유료 구독도 실제로 결제하지 않았고,
> `src/**`는 전혀 수정하지 않았다. 실제 제공자 통합·과금 결정은 사용자 승인과 별도
> 작업 계약(Codex 구현)이 필요하다.

## 배경

`research/reports/track-b-short-term-reversal-validation.md`까지 순수 가격 기반
Track B 후보 5종(Track A 규칙 재사용, 횡단면 모멘텀 3연속, MACD, 단기 반전)이 전부
기각됐다. 남은 후보(PEG/PER 밸류에이션, 저변동성+퀄리티 팩터)는 이 코드베이스가 현재
펀더멘털(재무제표·PE·PEG·수익성 지표) 제공자를 전혀 갖고 있지 않아 착수할 수 없었다
(`src/main/java/com/tradeguide/domain/market/MarketDataProvider.java`의 3개 제공자
- `TWELVE_DATA`, `TOSS_SECURITIES`, `YAHOO_FINANCE` - 전부 가격·캔들 전용).

사용자가 "(a) 펀더멘털 데이터 제공자 도입 검토"를 선택해, 실제 통합을 시작하기 전에
**어떤 제공자가 현실적인 선택지인지, 무엇을 풀고 무엇을 못 푸는지**를 먼저 정리한다.

## 핵심 결론 (2026-09-16 실제 API 테스트 후 수정)

**이 절은 최초 작성 후 실제 API 호출로 검증한 결과를 반영해 수정한 버전이다.** 최초
작성 시에는 공식 문서(마케팅 페이지) 표기만 보고 "두 제공자 모두 현재 스냅샷만 제공하고
시점별 과거 이력은 없다"고 판단했다. **사용자가 무료 Finnhub API 키를 발급해 실제
`/stock/metric` 엔드포인트를 AAPL로 호출해본 결과, 이 판단이 틀렸다는 것이 확인됐다.**
Finnhub 무료 티어는 PE·EPS·ROE·마진·부채비율 등 주요 비율의 **연간·분기별 시계열을
연도별 실제 값으로 제공한다**(AAPL 기준 연간 PE가 2000~2025년까지 26개 시점, EPS·유동
비율은 1985~2025년까지 41개 시점) - "지금 이 순간의 스냅샷 하나"가 아니라 **매 회계
연도 말 시점의 실제 비율값 시계열**이다. 이는 최초 판단보다 훨씬 유리한 결과이며,
PEG/PER 밸류에이션이나 퀄리티 팩터 후보의 워크포워드 백테스트를 **무료로 시도해볼 수**
**있는 근거가 된다.** 다만 이것이 학술적 의미의 완전한 point-in-time 데이터(재무제표
정정·재작성 반영 여부, 실제 공시일 기준 데이터 가용성)와 완전히 같지는 않다는 점은
아래 3.5절에서 별도로 짚는다 - "훨씬 나아졌다"이지 "문제가 완전히 해결됐다"는 아니다.

## 2. 후보 제공자 비교 (2026-09-16 조사)

### ① Twelve Data Pro 업그레이드 (이미 연동된 제공자)

- **가격**: Pro $99/월 (Basic 무료 → Grow $29/월 → **Pro $99/월** → Ultra $329/월).
  펀더멘털(재무제표, Statistics, Earnings/Earnings estimate/Revenue estimate)은
  **Pro부터** 포함된다 - Basic/Grow에는 없다.
- **장점**: 이 프로젝트가 이미 Twelve Data API 클라이언트·인증·요청 제한 처리 코드를
  갖고 있다(`docs/PROJECT_CONTEXT.md` 69·72행 - 가격·캔들·종목 검색에 이미 사용 중).
  같은 제공자를 확장하면 **새 인증·클라이언트·에러 처리 파이프라인을 새로 만들 필요가
  없다** - 통합 비용(개발 시간) 관점에서 가장 저렴한 경로.
  - 어떤 요금제를 현재 쓰고 있는지는 이 코드에서 확인할 수 없다(API 키는 코드/로그에
    남기지 않는 것이 프로젝트 원칙) - 이미 Pro 이상이면 추가 결제 없이 바로 쓸 수
    있을 수도 있다. **사용자가 현재 플랜을 확인해 알려줘야 한다.**
- **한계**: 공식 문서상 재무제표·Statistics 엔드포인트가 "현재/최근" 스냅샷인지
  시점별 이력을 지원하는지 명확히 표기돼 있지 않다(WebFetch로 확인한 결과, 배당·분할·
  실적 발표는 "캘린더" 형태로 이력이 있지만, Statistics는 "current snapshot"으로
  보인다). **실제 시점별 이력 제공 여부는 유료 구독 후 API 응답으로 직접 검증해야
  확정할 수 있다** - 이 조사만으로 100% 확신할 수 없다는 것을 명시한다.

### ② Finnhub 무료 티어 (신규 제공자)

- **가격**: 무료($0/월), 분당 60회 호출. 유료 All-in-One 플랜은 $3,500/월(연간 결제) -
  이 프로젝트 규모에는 비현실적으로 비싸다.
- **제공 데이터(무료 티어에서 확인)**: `Basic Financials`(P/E, EPS, 시가총액, 발행주식수,
  마진 등) 엔드포인트는 "High Usage"로 표기되어 있고(Finnhub API 문서, finnhub.io/docs,
  2026-09-16 조회) **무료 티어에서 접근 가능**하다 - `Financials`(전체 재무제표),
  `Ownership`, `Price Target` 등은 "Premium"으로 표기되어 $3,500/월 플랜에서만
  제공된다.
- **한계**:
  1. **신규 제공자 통합 비용**: 이 코드베이스에 Finnhub 클라이언트·인증·에러 처리를
     새로 만들어야 한다(`MarketDataProvider` enum에 새 항목 추가, 새 API 키 관리
     - 프로젝트 원칙상 코드/로그에 남기지 않고 환경변수로만 관리해야 함).
  2. 무료 티어의 `Basic Financials`가 PEG를 직접 제공하는지, PE/성장률로 계산해야
     하는지는 실제 API 응답 스키마를 유료 없이도 확인할 수 있으므로(무료 키 발급 후
     테스트 호출), 이번 조사에서는 문서 표기(P/E, EPS 등 포함)까지만 확인했고 필드
     단위 정확한 스키마는 **실제 테스트 호출로 재확인이 필요**하다.
  3. 이 무료 엔드포인트도 "현재" 스냅샷 중심이다(과거 특정 시점의 P/E를 그 시점에
     실제로 알 수 있었던 값 그대로 조회하는 point-in-time 이력 API는 무료 티어에
     없다).

### ③ (참고, 이번에 상세 조사하지 않음) CRSP/Compustat급 유료 point-in-time 데이터

  제기되면 별도 조사 작업으로 분리해야 한다.

## 3.5. 실제 API 테스트 결과 (2026-09-16, AAPL, 무료 Finnhub 키)

- **호출**: `GET /api/v1/stock/metric?symbol=AAPL&metric=all` (문서 기준 "High Usage",
  무료 티어 포함). 키는 사용자가 발급해 `.env`(git-ignored)에 저장했고, 이 문서·코드·
  로그 어디에도 실제 키 값을 기록하지 않았다.
- **응답 구조**: 최상위에 `metric`(133개 필드, 최신 값 위주 - PE/PEG/ROE/마진/성장률 등),
  `series.annual`/`series.quarterly`(39개 지표, 각각 `[{period, v}, ...]` 형태의 진짜
  시계열)가 있다.
- **PE 연간 시계열 확인**(AAPL, `series.annual.pe`): 2025년 33.56, 2024년 37.58, 2023년
  27.86 ... 2003년 111.90, 2002년 80.06, 2001년 결측(None), 2000년 10.03까지 26개 연도.
  값이 연도마다 크게 다르게 변동하는 패턴이 실제 그 시점의 주가/실적 조합과 부합해,
  "오늘 가격 ÷ 과거 실적"으로 역산한 가짜 시계열이 아니라 **각 회계연도 시점 기준의
  실제 비율**로 보인다.
- **PEG 자체는 시계열에 없다** - `metric`에 `pegTTM`(최신 1개 값)만 있고
  `series.annual`/`series.quarterly`에 `peg` 키는 없다. PEG를 시계열로 쓰려면 `pe`
  시계열과 EPS 성장률을 조합해 직접 계산해야 한다(추가 엔지니어링, 이번 조사 범위 밖).
- **유용한 시계열 지표(둘 다 annual/quarterly)**: `pe`, `pb`, `ps`, `ptbv`, `pfcf`,
  `roa`, `roe`, `roic`, `grossMargin`, `netMargin`, `operatingMargin`,
  `totalDebtToEquity`, `currentRatio`, `quickRatio`, `eps`, `bookValue`,
  `evEbitda`/`evRevenue` 등 - 밸류에이션(②)과 퀄리티 팩터(④)의 "퀄리티 절반"에
  필요한 지표 대부분이 실제로 시계열로 존재한다.
- **아직 남은 한계 (완전한 point-in-time과의 차이, 명시적으로 밝힘)**:
  1. **재무제표 재작성(restatement) 미반영 가능성**: 이 시계열이 "당시 최초 공시된
     숫자"인지 "이후 정정된 최신 숫자"인지 API 응답만으로는 알 수 없다 - 대부분의
     무료/중가 제공자는 최신 재작성치를 과거 시점에 소급 반영하는 방식이라, 극히 드문
     회계 정정 사례에서 미세한 미래참조가 생길 수 있다.
  2. **공시일(실제 발표일) vs 회계기간 종료일**: `period` 필드가 회계연도/분기
     **종료일**이지, 실제 그 실적이 **공개된 날짜**가 아니다. 예를 들어 9월 결산
     기업의 실적은 통상 10월 말~11월에 발표된다 - 이 시차를 무시하고 "period일에 이미
     이 값을 알 수 있었다"고 가정하면 명백한 미래참조(look-ahead bias)가 된다.
     **워크포워드 백테스트에 쓰려면 반드시 발표일 지연(예: 회계기간 종료 후 45~90일
     버퍼)을 명시적으로 반영해야 한다** - 이번 조사에서는 이 지연을 아직 설계하지
     않았다(다음 작업 계약에서 사전 등록 필요).
  3. **유니버스 시점별 편입 이력은 여전히 없음** - 이 엔드포인트는 종목별 데이터라서,
     "2018년에 S&P500에 있던 종목 목록"이라는 별개 문제(모멘텀 검증에서 계속 caveats로
     남긴 생존편향 이슈)는 그대로 남는다. Track B 밸류에이션 후보를 검증하려면 이번
     모멘텀 검증에 썼던 것과 같은 방식(오늘 시점 S&P100 목록을 소급 적용,
     `pointInTimeUniverse=false`로 명시)을 그대로 재사용해야 한다.
  4. 무료 티어 분당 60회 제한 - S&P100 101종목을 한 번 스캔하는 데 약 2분 소요(기존
     Yahoo Finance 가격 수집과 비슷한 처리 시간), 무리 없는 수준이다.

## 3. 이 결정이 실제로 푸는 것과 못 푸는 것

| 하고 싶은 일 | Twelve Data Pro 또는 Finnhub 무료로 가능한가 |
|---|---|
| Track B 후보 스크리닝(`candidates.json`)을 수동 Finviz 조회 대신 자동 API 호출로 정기 갱신 | **가능** - 두 제공자 모두 오늘 시점 PE/PEG류 지표를 API로 제공 |
| PEG/PER 밴드 전략(②)을 오늘 시점 기준으로 라이브 후보 추천에 반영 | **가능** (단, ①의 "자동 매수 신호 아님" 원칙은 유지) |
| PEG/PER 또는 퀄리티 팩터를 2015~2026 워크포워드로 **백테스트**해서 채택 게이트를 통과하는지 검증 | **Finnhub 무료 티어로 시도 가능 (수정된 판단)** - `series.annual`/`series.quarterly`가 실제 연도별 PE/PB/ROE/마진 등 시계열을 제공한다. 단, 공시일 지연(3.5절 한계 2번)을 반드시 설계에 반영해야 하고, 유니버스는 여전히 `pointInTimeUniverse=false`(오늘 시점 S&P100 소급) 한계가 남는다 |
| 저변동성 팩터의 "퀄리티" 절반(수익성·재무건전성) 실행 | **가능(수정된 판단)** - ROE/ROA/마진/부채비율 시계열이 실제로 존재해 퀄리티 스코어를 과거 시점별로 계산할 수 있다. 저변동성 절반(가격 표준편차)은 이미 보유한 Yahoo Finance 가격 데이터로 가능 - 둘을 합친 퀄리티+저변동성 팩터(④)를 이제 실제로 시도해볼 수 있다 |

## 4. 권고 (2026-09-16 실제 API 테스트 후 수정)

1. **Finnhub 무료 티어가 Track B 밸류에이션/퀄리티 팩터 워크포워드 백테스트를 무료로**
   **시도해볼 수 있는 현실적인 다음 단계다.** 비용 부담이 없고(월 $0), 이미 API 키
   발급·테스트 호출까지 완료했다(3.5절). 유료 결정 없이 바로 다음 리서치 작업(공시일
   지연을 반영한 PEG/PER 또는 퀄리티+저변동성 팩터 워크포워드 백테스트 설계)으로
   진행할 수 있다.
2. **다음 리서치 작업으로 제안**: S&P100 101종목(기존 확보된 유니버스 재사용)에 대해
   Finnhub `series.annual`/`series.quarterly`의 PE·ROE·마진·부채비율 등을 수집하고,
   공시일 지연(사전 등록 필요 - 예: 회계기간 종료 후 60일 버퍼, 데이터를 보기 전에
   고정)을 반영해 퀄리티+저변동성 팩터(④) 또는 PEG/PER 밴드(②) 중 하나를 새 사전
   등록 가설로 워크포워드 백테스트하는 것을 다음 작업으로 제안한다. 어느 쪽을 먼저
   할지는 사용자 확인이 필요하다.
3. **Twelve Data Pro 업그레이드는 이제 우선순위가 낮다** - Finnhub 무료 티어로 이미
   필요한 시계열을 확인했으므로, 유료 대안을 먼저 검토할 이유가 줄었다. Twelve Data는
   Finnhub 무료 한도(분당 60회)로 부족해지는 경우에만 재검토한다.
4. **백테스트 가능한 완전한 point-in-time 데이터(③, CRSP/Compustat급)는 여전히 도입을**
   **권고하지 않는다** - Finnhub 무료 데이터의 잔여 한계(재작성 미반영 가능성, 유니버스
   생존편향)는 이미 알려진 caveat으로 관리 가능한 수준이라고 판단한다.
5. 실제 제공자를 제품 코드(`MarketDataProvider` enum 등)에 통합하는 것은 이번 조사
   범위 밖이다 - 지금 한 것은 `research/` 범위 안에서의 무료 API 테스트 호출 1회일
   뿐이며, 백테스트 결과가 채택 게이트를 통과해야만 실제 제품 통합(별도 작업 계약,
   Codex 구현)을 검토한다.
