## 1. 결론과 목표

만들어야 할 것은 단일 종가를 맞히는 모델이 아니라 **세션별 가격 시나리오를 예측하고, 실제 보유량·현금·위험 제약을 적용해 조건별 매수·매도 가격과 수량을 산출하는 시스템**이다.

출력은 `BUY/SELL/HOLD`에서 끝나지 않는다. 다음 정보를 함께 제공한다.

- 보유 종목: 추가 매수, 부분 익절, 부분 위험 축소, 잔여 전량 청산 또는 관망.
- 신규 종목: 편입 후보, 매수 조건·가격·수량·필요 현금, 기존 포트폴리오와의 중복 위험.
- 각 행동: 적용 세션, 유효기간, 선행 조건, 무효화 조건, 주문 종류, 다른 주문과의 충돌 관계.
- 근거: 기본적·기술적·거시·심리 요인, 데이터 기준 시각, 검증 범위와 불확실성.
- 실행 가능성: 예약 주문 가능 / 사용자 확인 후 실행 / 데이터 부족으로 산출 불가.

수익을 보장하거나 매일 거래를 강제하지 않는다. 검증되지 않은 상태에서는 숫자가 그럴듯하더라도 실행 가능한 추천으로 승격하지 않는다. 자동 주문 전송은 이번 범위에 포함하지 않는다.

## 2. 기존 프로젝트와의 차이

2026-09-21에 읽은 현재 작업 트리 기준이다. 다른 에이전트의 완료 보고만으로 판단하지 않았다.

| 구분 | 현재 확인한 내용 | 필요한 변화 |
|---|---|---|
| 전략 신호 | Track A의 완성 주봉 추세 중심 | 세션별 가격 분포·조건 성립 확률 추가 |
| 손절 | 사용자 손절 기준과 보유량을 이용한 보호적 청산 초안 | 전략 무효화 가격 추천과 사용자 허용 위험을 별도 적용 |
| 매수 수량 | 위험 한도·종목 노출 한도로 계산 | 주문 가능 현금·기존 예약·수수료·다른 후보와의 경쟁 반영 |
| 통화 | 해당 계획 서비스에서 USD 평가 합계 사용 | KRW/USD 별 자금 제약, 환산 평가와 실제 주문 가능 자금 구별 |
| 매도 계획 | 보호적 청산 등 기존 행동 유형 | 부분 익절·부분 손절·잔여 수량 관리 |
| 연구 | 여러 전략의 장기 수익률 비교 | 예측 정확도, 체결 가능성, 포트폴리오 정책을 각각 검증 |

근거 코드: `src/main/java/com/tradeguide/service/strategy/TradePlanPreviewService.java`의 USD 평가 합계 사용(130행), 수량 계산(425~459행 부근), `AVAILABLE_CASH_NOT_SYNCED` 제약. 이는 프로젝트 전체에 현금 관련 기능이 전혀 없다는 뜻이 아니라 **이 계획 계산 경로가 주문 가능 현금과 결합되지 않았다는 뜻**이다.

기존 `StrategySignal → StrategyDecision → TradePlan` 구분, 계좌 연동·원장·스냅샷·장전 가이드 저장 기능은 재사용한다. 기존 Track B 기각 결과를 뒤집거나 새 엔진을 자동으로 Track B에 등록하지 않는다.

### 기존 연구에서 보완할 증거

- `research/scripts/track-b-walk-forward/quality_lowvol_factor_backtest.py`는 회계기간 종료일에 75일을 더해 정보 가용일을 근사한다(69·120행). 실제 공시 시각과 과거 수정 이력을 확인한 엄격한 point-in-time 데이터와는 다르다. 이 사실만으로 모든 결과가 잘못됐다고 단정할 수는 없지만 증거 등급을 구분해야 한다.
- `research/reports/track-b-market-concentration-diagnosis.md`의 사후 고수익 기여 종목 제외 분석은 성과 차이의 민감도 분석이다. 미래의 승자를 미리 제외할 수 없으므로 전략 유효성에 대한 인과적 증명으로 사용하지 않는다.
- 과거 구성 종목·상장폐지 종목 포함 여부를 재확인한다. 고정 종목군이었다면 생존 편향 가능성을 별도 표시한다.
- 겹치는 검증 기간은 독립적인 반복 검증 횟수로 세지 않는다. 이미 반복 탐색한 기간은 새로운 미사용 최종 시험 구간으로 부르지 않는다.

## 4. 두 시간축과 거래 세션

### 투자 후보와 당일 주문을 분리

| 계층 | 1차 실험의 예측 대상 | 용도 |
|---|---|---|
| 후보 선정 | 향후 20거래일 업종 대비 수익과 하방 위험 | 무엇을 편입·축소할지 |
| 전술 가격 | 다음 세션의 고가·저가·종가 분포, 조건별 결과 | 어느 가격에서 어떤 행동을 할지 |
| 위험 관리 | 세션 중 급락·갭·동반 하락 시 포트폴리오 손실 | 몇 주까지 허용할지 |

20거래일은 초기 실험의 고정 가설이다. 성적이 안 좋다고 여러 기간을 무제한 시도하지 않는다. 장기 기업가치 정보가 다음 몇 분의 가격까지 설명한다고 가정하지 않는다.

### 세션 계약

- 미국: 정규장·프리마켓·애프터마켓·브로커가 제공하는 오버나이트를 서로 다른 세션으로 취급한다. 사용자가 부르는 '데이장'은 브로커와 거래소 시간으로 명시적으로 매핑한다.
- 한국: KRX와 NXT, 각 거래 구간 및 거래 가능 종목을 구별한다. 모든 종목에 모든 세션이 있다고 가정하지 않는다.
- `exchangeTimezone`, `sessionId`, `tradingDate`, `startsAt`, `endsAt`, `cutoffAt`을 저장한다. 한국 시각 고정 예약 대신 현지 달력·휴장·서머타임을 사용한다.
- 초안 생성은 시작 30분 전, 데이터 확인은 시작 5분 전을 초기 운영 제안으로 둔다. 이 간격은 예측 성능이 검증된 숫자가 아니다.
- 생성 시점 이후 데이터는 그 가이드의 입력으로 넣지 않는다. 새로운 정보로 바뀐 가이드는 별도 버전이다.
- 세션 종료·중요 공시·포트폴리오 변경·데이터 오류 발생 시 만료/재검토한다. 기존 예약 주문은 시스템 가이드 변경만으로 취소되지 않음을 표시한다.

장외 세션은 유동성·주문 지원 조건이 다르므로 정규장 백테스트로 대신 인증하지 않는다. [FINRA 장외 거래 안내](https://www.finra.org/investors/insights/extended-hours-trading), [NXT 시장 안내](https://nextrade.co.kr/marketOverview/content.do).

## 5. 입력 데이터와 정보 시점

| 범주 | 초기 후보 특징 | 중요 제한 |
|---|---|---|
| 기본적 | 수익성, 영업현금흐름, 부채, 매출·이익 변화, 업종 대비 밸류에이션 | 회계기간 말일이 아니라 공시 이후에만 사용 |
| 기술적 | 다중 기간 수익률, 추세, ATR·실현 변동성, 거래대금, 거래량 변화, 갭, 지지·저항 후보 | 미완성 봉을 완성 봉처럼 사용하지 않음 |
| 거시 | 금리·금리차, 환율, 시장·업종 수익, 신용 위험, 예정된 물가·정책 발표 | 당시 공개된 값과 발표 시각, 수정 전 vintage |
| 심리 | 공시·뉴스 사건과 방향, 변동성 지표, 투자자 수급, 이용 가능한 옵션 지표 | 뉴스 중복·출처·게시/수집 시각, 결측을 중립으로 둔갑시키지 않음 |
| 개인계좌 | 수량, 평균단가, 주문 가능 현금, 미체결 주문, 예약, 동기화 시각 | 증권사별 주문 가능 금액과 단순 현금 잔액이 다를 수 있음 |

MACD와 RSI는 후보 특징이다. 보편적으로 우월한 매매 규칙이라고 가정하지 않는다. 각 데이터 묶음을 추가/제거한 비교 실험으로 실제 기여를 확인한다.

ETF에는 기업 ROE를 억지로 적용하지 않는다. SOXL 같은 레버리지 ETF는 기초지수·구성 섹터·레버리지·경로 의존 위험을 따로 모델링하며 일반 주식과 동일한 위험 한도로 자동 취급하지 않는다.

### 공급원과 비용 경계

- 운영 시세·계좌: 사용자 설정 공급자를 우선한다. 토스 공식 문서는 국내·미국 시세, 캔들, 계좌 및 조건주문을 설명한다. 다만 **필요 연수의 세션별 분봉·과거 호가·상장폐지 데이터·재배포 권한까지 충분하다는 뜻은 아니다**. 인증정보 없이 문서상 기능만 확인했다. [토스 공식 문서](https://developers.tossinvest.com/).
- 미국 공시: SEC submissions/XBRL을 공시 식별자·접수 시각과 연결한다. 현재 companyfacts의 최신 값만 내려받아 과거 전체에 적용하지 않는다. [SEC API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces).
- 한국 공시: DART를 활용하되 공시일·정정공시·종목 식별자 연결을 보존한다. 오래된 위기 구간까지 동일 품질로 확보된다고 가정하지 않는다. [Open DART](https://opendart.fss.or.kr/).
- 거시: FRED/ALFRED의 과거 알려진 값 조회를 활용한다. 한국 거시 데이터도 발표 당시 값을 확보할 수 있는지 별도 조사한다. [FRED 실시간 기간/vintage](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html).
- 뉴스·장기 분봉·호가·과거 지수 편입 정보는 비용과 라이선스가 핵심 제약이다. 공개 API가 있다고 학습·저장·대고객 표시 권한이 자동 확보되지는 않는다.

운영 공급자와 연구 데이터 공급자는 달라도 되지만 동일 기간의 시각·가격 조정·세션·결측 차이를 검증한다. Yahoo를 개발 대체 데이터로 쓰더라도 운영 데이터와 동등하거나 서비스 이용 권한이 확인됐다고 간주하지 않는다. 공급자 변경은 숨기지 않는다.

### 반드시 저장할 시각

`eventAt`(시장/사건 발생), `publishedAt`(외부 공개), `receivedAt`(시스템 수신), `availableAt`(이 실험에서 사용 가능), `revisionId`, `source`, `qualityFlags`.

학습 시 모든 특징은 `availableAt <= cutoffAt`을 만족해야 한다. 실제 수신 이력이 없는 과거 복원 데이터는 공개 시각 기반의 가정과 지연을 명시하고, 실제 운영 재현으로 과장하지 않는다. 수정된 거시·재무 데이터와 기업행위도 버전을 보존한다.

## 6. 모델 구조: 작은 비교에서 시작

```text
공급자 데이터 + 계좌 스냅샷
  → 시점·품질·거래 가능성 검사
  → 시장/업종 상태 + 네 범주의 특징
  → 신규 후보 순위 + 가격 분포/조건 결과 예측
  → 현금·수량·위험을 제한하는 행동 계획
  → 주문 종류·세션 지원 검사
  → 근거·만료 조건과 함께 저장/표시
```

### 비교 모델 3개만 먼저 고정

1. **M0 기준선:** 기존 Track A와 단순 변동성 기반 가격 범위. 기존 엔진은 그대로 비교 대상으로 남긴다.
2. **M1 단순 통계:** 정규화된 회귀/분위수 회귀, 로지스틱 확률 모형. 복잡한 모델의 추가 효과를 확인한다.
3. **M2 비선형:** LightGBM으로 후보 순위·수익/가격 분위수·조건부 결과를 학습한다. 학습 과제별 모델은 분리하되 특징·데이터 버전은 공통 관리한다.

LightGBM은 분위수·분류·순위 관련 목적함수를 제공하므로 비교 후보로 적합하다. 선정 자체가 수익성의 증거는 아니다. [공식 파라미터 문서](https://lightgbm.readthedocs.io/en/latest/Parameters.html).

처음부터 강화학습·대형 시계열 Transformer·LLM 직접 가격 예측을 도입하지 않는다. 데이터와 정책 검증이 먼저다. LLM은 출처가 있는 뉴스의 구조화와 **계산 완료된 결과의 설명**에 한정하고 가격·수량을 임의로 바꾸지 못하게 한다. 현재 LLM이 과거 사건의 이후 결과를 이미 학습했을 수 있으므로 과거 뉴스에 대한 LLM 성능은 별도 누출 위험을 가진다. 고정 모델·절제된 입력·전향적 검증이 필요하다.

### 정확한 예측 목표

- 가격은 절대 금액이 아니라 기준 시점 대비 수익률·변동성으로 정규화한다.
- 다음 세션의 저가/고가/종가 분위수를 예측한다. 고가·저가 분포는 체결을 보장하지 않으며 서로의 독립 결합으로 경로를 만들어서는 안 된다.
- 매수/손절/익절 후보 조합마다 `진입 후 목표 선도달 / 손절 선도달 / 시간 종료 / 미진입` 결과를 정의한다. 세션 경계와 관측 순서를 보존한다.
- 거래 이후 수익률의 조건부 분포와 비용을 함께 평가한다. 목표가 도달 확률, 체결 확률, 순이익 확률을 같은 '신뢰도'로 혼합하지 않는다.
- 검증 구간에서 확률 보정을 수행하고, 최종 시험에는 보정기를 고정한다. 표본 부족이면 숫자 신뢰도를 표시하지 않는다.

가격 후보는 모델 분포와 과거 가격 구조에서 제한된 개수로 만들고, 검증 전에 고정한 정책 조합으로 평가한다. 분위수 10%를 기계적으로 손절가, 90%를 목표가로 지정하지 않는다.

### 가격 산출의 재현 가능한 절차

1. 가이드 cutoff의 거래 가능한 기준가격 `P0`와 특징을 고정한다. 평균매입가는 손익 설명용이며 미래 가격의 중심으로 강제하지 않는다.
2. 저가·고가·종가 수익률의 예측 분위수에서 `P = P0 × (1 + 예측 수익률)`로 소수의 가격 후보를 만든다. 예를 들어 가상의 저가 수익률 후보가 -5%이고 `P0=200,000`이면 190,000원이 후보가 된다. 이것만으로 매수 추천이 확정되지는 않는다.
3. 초기 연구의 후보 분위수 집합은 {0.2, 0.5, 0.8}로 제한하는 안을 제안한다. 여기에 사전에 정의한 가격 구조/변동성 기준을 비교하며, 이 집합과 규칙은 시험 전에 고정한다. 호가단위로 보수적으로 변환한 뒤 진입·손절·목표의 순서가 유효한 조합만 남긴다.
4. 후보 조합별 진입 및 진입 후 목표/손절 선도달 결과를 과거 경로에서 라벨링한다. 라벨을 미리 정한 동일한 규칙으로 만들어 후보 가격과 진입 시점의 상태를 조건으로 학습한다.
5. 각 조합의 비용 후 손익과 하방 위험을 검증한다. 비용 후 우위가 없으면 그 가격은 출력에서 제외하고 관망한다. 확률 오차와 표본 부족도 제외 이유다.
6. 다단계 주문은 각 단계의 예측 확률을 독립적으로 곱하지 않는다. 상태 전이를 포함한 계획 전체를 과거 경로에 재생하고 평가한다. 결합 경로를 충분히 검증하지 못하면 하나의 진입/청산 계획으로 축소한다.

이 절차의 핵심은 '지지선이라서 190,000원'이라는 설명만 남기는 것이 아니라 **후보 생성 → 조건별 결과 예측 → 비용/위험 평가 → 탈락 또는 채택**의 기록을 남기는 것이다.

## 7. 가격을 실제 행동으로 바꾸는 정책

각 후보 계획의 비교 목적은 다음 형태로 둔다.

```text
계획 가치 = 비용 차감 후 기대 손익
          - 하방 손실 위험 페널티
          - 거래 비용/회전·집중 위험 페널티
```

단위와 가중치를 검증 전에 고정한다. 위험 페널티를 수익이 좋아 보이도록 시험 구간에서 조정하지 않는다. 관망 계획도 항상 비교에 포함한다.

사용자 위험 한도는 예측기가 임의로 늘릴 수 없는 상한이다. 전략 모델은 시장 구조·변동성·시나리오 붕괴를 근거로 손절 후보를 제시한다. 그 손절 폭에 맞춰 수량을 줄이며, 주문을 가능하게 하려고 손절을 부자연스럽게 좁히지 않는다. 기존 보유 종목의 추천 손절도 사용자 정책을 자동 변경하지 않고 승인/검토 사항으로 제시한다.

### 수량 계산

```text
기준 순자산 = 보유자산 평가 + 현금 - 부채  (일관된 환산 시각)
주문 가용 현금 = 브로커 주문가능액 - 이 시스템에서 아직 미반영된 예약 필요액
한 주 위험액 = 진입가 - 손절 후보가 + 보수적 비용/슬리피지 추정

신규 매수 상한 = lot 단위 내림(
  min(할당 손실예산 / 한 주 위험액,
      해당 통화 가용 현금 / 비용 포함 진입가,
      종목·업종 노출 여유 / 진입가,
      유동성 기반 수량 상한)
)
```

브로커 주문가능액이 이미 예약을 차감했다면 다시 차감하지 않는다. 미체결 매도대금을 확정 자금처럼 사용하지 않는다. USD 평가액으로 KRW 주문을 가능하다고 판단하지 않는다. 초기 버전은 환전 자동 가정 없이 통화별 자금 묶음으로 제한한다.

부분 매도 수량은 미리 고정한 제한된 선택지(예: 목표 비중으로 축소, 보유의 일부, 잔여 전량)를 평가한다. 기존 예약을 포함해 어느 가능한 체결 경로에서도 공매도·현금 초과가 발생하지 않아야 한다. 같은 종목뿐 아니라 SOXL·삼성전자·SK하이닉스의 반도체 위험 중복도 점검한다.

손절가까지의 손실 추정은 최대 손실의 보장이 아니다. 갭·거래정지·미체결 시 초과 손실을 스트레스 테스트한다. 현금·수량·가격이 오래됐거나 확인되지 않으면 확정 수량을 제시하지 않는다.

수량 계산의 가상 예: 진입 190,000원, 손절 후보 180,000원, 주당 왕복 비용·슬리피지 추정 500원, 해당 계획의 손실예산 12,000원이면 위험 기준 수량은 `floor(12,000 / 10,500) = 1주`다. 가용 현금 2,500,000원, 주당 진입 비용 250원이면 현금 기준은 13주다. 노출 한도 여유 2,000,000원이면 가격 기준 10주이며, 유동성 한도가 더 작지 않다는 가정에서 최종 1주가 된다. 비용은 예시용이며 실제 수수료 체계를 뜻하지 않는다. 부분 매도는 목표 잔여량과 현재 보유량의 차이로 계산하므로 5주에서 목표 잔여량 2주라면 3주다. 목표 잔여량 자체는 위 정책 평가의 결과여야 한다.

### 신규 종목 추천

과거 시점별 투자 가능 종목군 → 거래 가능성·데이터·유동성 필터 → 업종 대비 후보 순위 → 기존 보유와 상관·집중 위험 → 실제 예산을 고려한 배분 순으로 처리한다. 모든 사용자에게 동일한 상위 상승 예상 종목을 복사하지 않는다. 최소 1주를 살 수 없으면 0주를 추천하는 대신 '예산 부족으로 편입 보류'를 표시한다. 추천할 후보가 없는 결과도 정상이다.

## 8. 사용자가 원하는 화면의 예시

**가상 상황:** 삼성전자 기준가와 평균단가 모두 200,000원, 5주 보유. 아래 가격·수량은 출력 구조 설명용이며 분석 결과나 실제 추천이 아니다.

| 시나리오 | 조건/가격 | 행동 | 실행상 의미 |
|---|---|---|---|
| 상승 목표 | 210,000원 이상 | 기존 보유에서 3주 익절 | 매도 지정가 후보 |
| 약세 전환 | 190,000원 하향 이탈 | 기존 보유에서 1주 위험 축소 | 하향 조건주문 후보, 단순 지정가 매도가 아님 |
| 가설 붕괴 | 예시 185,000원 하향 이탈 | 실제 잔여 수량 청산 | 앞선 체결을 반영한 잔여량으로만 실행 |
| 대체 매수 시나리오 | 별도 반등 조건을 충족한 후 190,000원 이하 | 1주 추가 매수 검토 | 약세 전환 매도와 상호 배타, 지원 안 되면 수동 검토 |
| 신규 후보 | SK하이닉스 예시 2,000,000원 | 한도 충족 시 1주 | 현금·수수료·반도체 집중 위험 미충족 시 보류 |

위 행들을 모두 독립 주문으로 한꺼번에 등록하라는 뜻이 아니다. 예를 들어 3주 익절 후 1주 위험 축소가 체결됐다면 마지막 청산은 1주다. 1주 추가 매수 분기는 별도 계획 버전이며, 익절·손절 수량을 재계산한다. 반등 조건은 구현 시 봉 종료·가격·거래량 등 측정 가능한 규칙으로 고정해야 하며 '반등 같아 보임'으로 두지 않는다.

현재가 200,000원에서 매도 지정가 190,000원을 넣으면 190,000원까지 기다리는 손절이 아니라 현재 더 좋은 가격에 체결될 수 있다. 따라서 트리거 가격과 실제 주문가격을 분리한다. 손절 시장가는 가격을 보장하지 않고, 손절 지정가는 미체결될 수 있다. [FINRA 주문 유형](https://www.finra.org/investors/investing/investment-products/stocks/order-types).

OCO/OTO나 잔여 수량 자동 축소 지원 여부를 브로커·종목·세션별로 확인한다. 단순 가격 예약으로 표현할 수 없는 복합 조건은 '예약 가능'으로 표시하지 않는다. 앱에 계획이 갱신되어도 증권사 기존 예약은 남아 있을 수 있으므로 취소·교체 확인이 필요하다.

## 9. IMF·반도체 호황은 배제해야 하는가?

**원칙적으로 배제하지 않는다. 호황과 위기에서 어떻게 작동하는지가 엔진의 중요한 검증 대상이다.**

| 상황 | 처리 |
|---|---|
| 반도체 호황·특정 업종 독주 | 전체 성과에 포함하고 업종·집중도별 성과를 추가 보고 |
| IMF·금융위기·팬데믹 급락 등 | 데이터가 있는 범위에서 포함, 별도 스트레스 성적표 작성 |
| 해당 시기 공시/심리/분봉이 없음 | 가격 기반 스트레스 등 검증 가능한 범위만 표시 |
| 당시 상품/거래 세션이 존재하지 않음 | 실제 거래 백테스트로 만들지 않음 |
| 오류 가격·중복·잘못된 조정 | 사전에 정한 정제 규칙에 따라 수정/제외하고 기록 |

학습은 구조 변화 때문에 최근 기간을 쓰거나 과거 표본을 낮게 가중할 수 있다. 다만 그 결정은 결과를 보기 전에 고정하며, 위기 평가를 삭제하는 근거로 쓰지 않는다. 1997년을 모든 특징이 존재하는 현대의 세션 거래처럼 복원하는 것도 부정확하다. 현대 데이터 기반 본 검증과 역사적 위기 스트레스를 분리한다.

시장 상태는 당시 관측 가능했던 추세·변동성·신용·집중도 등으로 계산한다. '나중에 보니 호황이었다'는 라벨은 사후 진단에는 쓸 수 있지만 당시 모델의 입력으로 넣을 수 없다. 국면별 약점을 확인하면 거래 축소/관망 정책을 별도 검증한다. 모멘텀 전략의 특정 시장 상태에서의 취약성은 기존 연구에서도 다뤄진다. [Momentum Crashes](https://www.nber.org/papers/w20439).

## 10. 백테스트: 예측과 의사결정을 분리 평가

### 검증 프로토콜

1. 대상 종목군·세션·특징·모델 수·평가 지표·비용·합격 기준을 결과 확인 전에 문서로 고정한다.
2. 시간 순서로 학습/검증/시험을 분리한다. 예: 학습 3~5년, 검증 6~12개월, 시험 6~12개월의 rolling 평가. 구간 길이는 데이터 감사 후 한 번 결정한다.
3. 모든 종목에 같은 시간 경계를 적용한다. 목표 기간이 다음 구간에 걸치는 표본은 제거하고 적절한 시간 간격을 둔다. 전처리·정규화·확률 보정도 학습/검증 범위 안에서만 한다.
4. 최종 미사용 시험 구간은 한 번 평가한다. 이미 여러 연구에서 본 과거는 미사용 구간으로 재분류하지 않는다. 필요하면 새롭게 쌓이는 모의운영 구간을 사용한다.
5. 모델뿐 아니라 가격·수량 정책까지 고정하고 평가한다. 가격 예측이 맞아도 정책·비용 때문에 손실이면 실패로 기록한다.
6. 수익과 위험을 시장·세션·업종·국면별로 보고한다. 네 분석 범주의 제거 실험으로 추가 가치와 데이터 비용을 비교한다.

### 체결 모형

가격별 분할 주문을 평가하려면 최소 세션별 분봉이 필요하다. 일봉 고가와 저가만으로 손절과 익절 중 먼저 발생한 것을 알 수 없다. 분봉에서도 동일 봉 내 순서가 불명확하면 보수적 경로 또는 상·하한 성과를 함께 보고한다. 호가·거래량이 없으면 체결 가능성 검증 수준을 낮게 표시한다.

호가 차이, 수수료·해당 시점 세금, 슬리피지, 환전 비용, 지연, 부분 체결, 거래정지, 갭, 호가단위·가격제한폭·분할/병합·배당을 포함한다. 실제 주문가격은 당시 원가격 기준, 분석용 조정가격과의 변환은 기업행위 이력으로 관리한다. 새로 생성한 주문을 생성 이전 봉에서 체결시키지 않는다.

실행 코어를 새로 손으로 만들기보다 기존 백테스트 기반과 [LEAN의 체결 모델](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)을 비교한다. LEAN은 [오픈소스 엔진](https://github.com/QuantConnect/Lean)이지만 한국 거래 규칙·세션·데이터 연결을 별도 구현/검증해야 한다. Java 운영 서비스를 LEAN으로 갈아엎는 제안은 아니다.

### 성적표와 승격 조건

| 층 | 지표/조건 |
|---|---|
| 데이터 | 미래 정보 사용 0건, 출처·기준 시각 누락 탐지, 과거 종목군 증명 |
| 예측 | 분위수 손실, 예측구간 실제 포함률, Brier/log loss, 확률 보정, 후보 순위의 구간별 안정성 |
| 정책 | 비용 후 수익, 변동성, 최대낙폭, 꼬리손실, 회전율, 체결률, 관망 비율, 유효 표본 수 |
| 비교 | 단순 보유, 기존 Track A, 현금, 유사 위험 수준 기준선과 공정 비교 |
| 안전 | 모든 경로에서 음수 현금·초과 매도·예약 중복 사용 0건 |
| 견고성 | 비용 증가·지연·데이터 결측·위기 구간에서 사전 위험 조건 충족 |

최고 수익률 한 줄로 합격시키지 않는다. 신규 편입은 사전 기준선 대비 비용 후 추가 가치가 있어야 하고, 위험 축소 기능은 사전에 정한 수익 포기 한도 안에서 하방 위험 개선 여부를 평가한다. 결과를 본 다음 목표를 바꿔 실패를 성공으로 부르지 않는다. 숫자 기준은 데이터 감사 후 첫 학습 전에 확정한다.

날짜/기간 단위 블록 재표본화로 불확실성을 추정하고, 종목별 거래를 모두 독립 표본으로 세지 않는다. 실험 횟수와 실패 결과를 남긴다. 여러 전략을 탐색했다면 선택 편향 조정도 보고하되 PBO/DSR 같은 값을 실제로 계산하지 않고 검증됐다고 쓰지 않는다. [백테스트 과적합 연구](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf).

20~60거래일 모의운영은 초기 동작 점검 제안이지 수익성 보증 기준이 아니다. 거래 표본·국면이 부족하면 기간이 지났어도 승격하지 않는다. 위기 한 번을 독립 위기 수십 번처럼 해석하지 않는다.

## 11. 기술 구조와 저장 계약

기존 Spring Boot·React·PostgreSQL을 유지한다. 연구 데이터는 Parquet와 manifest로 보관하고 모델 실험은 Python 배치로 분리한다. 대형 분산 시스템·실시간 Kafka·별도 벡터 DB는 초기 요구가 아니다.

| 도구 | 도입 목적과 비용/부담 | 대안/결정 |
|---|---|---|
| LightGBM·scikit-learn | CPU 중심 비교 모델, 라이브러리는 오픈소스. 데이터 준비와 검증 비용이 더 큼 | 단순 모형을 먼저, 유의한 개선 없으면 복잡한 모델 폐기 |
| LEAN | 이벤트 기반 체결·회계 기반 재사용, 오픈소스. 별도 런타임·국내 어댑터 부담 | 기존 엔진이 동등 검증을 통과하면 유지; 호스팅/데이터 비용은 별도 |
| Qlib | 표준화된 연구 구조 참고, 오픈소스. 전체 도입은 기존 구조 중복 가능 | 초기에는 참고·비교에 한정 |
| PostgreSQL + Parquet | 사용자별 계획 이력과 대량 연구 데이터를 분리 | 새 운영 DB를 추가하지 않음 |

Python이 학습·추론하고 Java가 계좌 권한·수량 정책·저장·API를 담당한다. 초기에는 버전이 고정된 배치 입출력으로 연결하고, 실시간 필요가 입증되면 추론 서비스로 분리한다. 양쪽의 금액·반올림·시각 계약을 fixture로 검증한다.

### 저장 대상(기존 테이블과 중복 여부 확인 후 확정)

- `model_version`, `research_run`: 데이터 manifest/hash, 코드 버전, 특징/정책 버전, 학습 종료 시각, 시험 성적, 승인 상태.
- `session_guide_snapshot`: 사용자/포트폴리오, 계좌·현금 스냅샷 버전, 세션, 데이터 기준 시각, 생성/만료, 품질 상태.
- `instrument_forecast`: 종목·시장·통화, 예측 기간, 가격 범위, 정의가 명확한 확률, 보정/표본 메타데이터.
- `trade_plan_leg`: 행동, 트리거·주문가격, 수량·금액, 손절/익절 구분, 선행/취소 조건, 충돌 그룹, 예약 가능 여부.
- `guide_feedback`: 사용자가 실행 확인한 주문과 실제 체결의 연결. 가이드를 생성한 사실과 거래한 사실을 혼합하지 않는다.

금액·수량은 decimal, API에서는 정밀도 손실을 피하는 문자열 계약을 검토한다. 종목 키는 티커 단독이 아닌 시장·거래소·영속 식별자를 포함한다. 모든 사용자별 조회는 소유권 검증을 통과해야 한다.

### 제안 API (아직 구현되지 않음)

```text
POST /api/portfolios/{portfolioId}/session-guides
  입력: sessionId, tradingDate, accountSnapshotVersion, policyVersion
  Idempotency-Key 지원; 202 + jobId

GET /api/portfolios/{portfolioId}/session-guide-jobs/{jobId}
GET /api/portfolios/{portfolioId}/session-guides/{guideId}
GET /api/portfolios/{portfolioId}/session-guides?cursor=...
```

중복 요청은 재계산 폭주를 막고 포트폴리오 변경 시 새 버전을 생성한다. 운영 상태와 종목별 결과를 분리해 `READY`, `PARTIAL`, `NO_ACTION`, `BLOCKED_DATA`, `EXPIRED`를 명확히 표시한다. 일부 종목 실패로 다른 정상 종목의 결과를 숨기지 않되, 포트폴리오 위험을 계산할 수 없다면 신규 수량 계획은 차단한다.

시장 데이터 공통 캐시는 공급자 약관·권한 범위 안에서만 공유한다. 계좌 스냅샷은 사용자별로 격리한다. 외부 AI에게 원본 인증키·개인 계좌를 넘기지 않는다. UI 새로고침마다 외부 API를 다시 호출하지 않도록 단일 요청 병합·캐시·요청 한도 관리를 적용한다.

## 12. UI와 안전한 안내

첫 화면은 '오늘 할 일 / 관망 / 산출 불가'를 구분하고 보유종목과 신규 후보를 분리한다. 세션 선택, 최신성, 가격 조건·수량·금액, 부분/전체 매도, 유효기간을 바로 보여준다. 상세 근거는 펼쳐서 확인한다. 확률이 없는 단계에서 임의의 신뢰도 %를 표시하지 않는다.

모바일에서는 `종목 → 행동 → 조건가격 → 수량/금액 → 만료` 순서를 유지한다. 긴 설명·오류·배지 유무가 버튼과 입력 필드 정렬을 바꾸지 않는지 중간 폭까지 테스트한다. 숫자만 복사하는 것보다 주문 유형·트리거와 함께 확인하도록 한다.

안내 문구 제안: '이 가이드는 과거 데이터와 가정에 따른 검토 정보이며 수익 또는 체결가격을 보장하지 않습니다. 최종 주문과 투자 판단은 사용자가 합니다. 손절 조건도 갭·유동성 부족 등으로 예상보다 큰 손실이 발생할 수 있습니다.'

이 안내를 모든 법적 책임이 사라지는 면책으로 해석하지 않는다. 대고객 제공 전에는 데이터 사용권과 서비스의 법적 성격을 별도 검토해야 한다. 이번 문서는 법률 적합성을 판단하지 않는다.

완성 목표는 두 시장과 여러 세션이지만, 동시에 운영 가능하다고 선언하지 않는다. 초기 실험은 두 시장의 제한된 검증 종목군과 정규장에서 시작하며, 일반화하지 않는다. 신규 후보 평가에는 당시 종목군 정보가 확보된 별도 범위가 필요하다.

첫 작업은 새로운 전략 10개 추가가 아니라 **데이터 커버리지 표와 평가 프로토콜 확정**이다. 다음 작업을 발주할 때는 파일 허용 범위, 입력·출력 계약, 테스트, 완료 증거를 함께 부여한다. 현재 문서는 역할 제안이며 에이전트에게 실제 발주했다고 보고하는 문서가 아니다.

### 반드시 통과할 회귀 테스트

- 동일한 과거 cutoff로 재생 시 이후 공시·수정 재무값을 사용하지 않음.
- 같은 종목 가격에서 매수/매도 대체 시나리오가 동시에 활성화되지 않음.
- 5주 보유에서 3주·1주 매도 후 잔여 청산은 1주이며, 순서가 바뀌어도 초과 매도 없음.
- 계좌별 현금·기존 예약·미체결·통화·소수점/정수 수량을 정확하게 반영.
- 부분 체결, 동일 봉 양방향 도달, 갭 하락, 거래정지, 분할/병합에서 낙관적 체결 없음.
- 미국 DST·휴장·한국 거래소 세션·미지원 종목에서 잘못된 예약 없음.
- 데이터 지연·429·공급자 변경·소유권 위반 시 낡거나 타인인 계획을 정상 결과로 제공하지 않음.
- 사용자 새로고침/재시도로 외부 호출·가이드·계획이 중복 생성되지 않음.

## 14. 아직 미확정인 사항

1. 투자 유지 기간: 후보 선정은 20거래일, 주문 계획은 다음 세션으로 가정했다. 초단타 전용 의도라면 특징·데이터·검증이 크게 달라진다.
2. 실제 확보 가능한 과거 분봉·호가·뉴스·공시 vintage 범위와 비용. 무료만으로 전체 목표를 충족한다고 약속하지 않는다.
3. 브로커별 세션·소수점·조건주문·부분 체결 후 수량 조정 지원. 계좌별 실증이 필요하다.
4. 비용 후 추가 가치 및 하방 위험에 대한 수치 합격선. 결과 확인 전 확정해야 한다.
5. 현재 프로덕션 전략으로 채택할지 여부. 연구가 성공했다고 자동 반영하지 않는다.

이번 산출물은 위 질문을 무제한 연구로 미루기 위한 문서가 아니라, **어떤 자료로 무엇을 만들고 무엇을 통과해야 다음 단계로 갈 수 있는지**를 고정하기 위한 설계다.
