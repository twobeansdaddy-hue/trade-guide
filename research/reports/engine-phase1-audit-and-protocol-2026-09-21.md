## 3. 기존 조사와 중복하지 않을 범위

다시 하지 않을 것: 기존 Track A/B 전략 전수 재실행, 같은 제공자 목록 재검색, MACD·ATR 등의 임의 재채택, 연구 결과가 나쁠 때 호황/위기 삭제.

추가할 것: 세션별 해상도, 정보 공개 시점, 당시 가격, 과거 종목군, 체결 순서를 증명하는 자료와 검사.

FRED 공식 문서는 기본값이 오늘 알려진 과거 정보이고 과거 알려진 값은 real-time 기간으로 구분한다고 설명한다. 따라서 최신 CSV 확보만으로 거시 PIT를 충족하지 않는다. [FRED 공식 문서](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)

SEC는 submissions와 XBRL 데이터를 제공한다. 따라서 기존 재무값에 고정 지연을 더하는 대신 공시별 접수 시각과 연결하는 최소 실험이 가능하다. 실제 매칭 성공률은 아직 확인하지 않았다. [SEC 공식 API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)

현재는 D0 착수 가능, D1은 사용할 입력별 감사 통과가 필요하며 D2는 자료 확보가 선행된다. 한국 시장을 최종 목표에서 제외하지 않는다. 한국 데이터가 주봉뿐인 상태에서 당일 가격 계획이 검증됐다고 보고하지 않는다.

## 5. 데이터 수용 계약 v0.1

각 데이터 묶음은 다음 필드를 가진 manifest와 연결한다.

```text
datasetId, schemaVersion, source, retrievedAt, contentHash
market, instrumentId, currency, timezone, interval, sessionCoverage
firstEventAt, lastEventAt, rowCount, adjustmentPolicy, corporateActionsRef
availabilityMode, publishedAtSource, vintagePolicy
universeMode, universeMembershipRef
licenseStatus, usageScope, evidenceRefs, limitations
```

- `availabilityMode`: ACTUAL_RECEIPT / PUBLICATION_RECONSTRUCTED / FIXED_LAG_APPROXIMATION / UNKNOWN.
- `adjustmentPolicy`: RAW / SPLIT_ADJUSTED / TOTAL_RETURN_ADJUSTED / UNKNOWN. 문서와 데이터가 충돌하면 UNKNOWN.
- `universeMode`: POINT_IN_TIME / FIXED_DIAGNOSTIC_SET / UNKNOWN.
- `sessionCoverage`: 정규장과 장외 세션을 명시적으로 열거. interval만으로 추정하지 않는다.
- 값이 없으면 추정해 채우지 않는다. UNKNOWN을 허용하되 해당 기능의 승인 조건을 통과하지 못하게 한다.
- 운영 가이드 학습 승인에는 출처/이용 범위 증거가 필요하다. 단순 다운로드 가능성과 이용권은 다르다.
- 자산별 사용 가능 여부를 따로 판정한다. 일부 종목 누락을 전체 성공으로 덮거나 정상 종목까지 모두 실패시키지 않는다.

## 6. 사전 검증 프로토콜 v0.1

상태는 **DRAFT_NOT_TRAINABLE**이다. 기술 안전 기준은 아래와 같이 정리했지만, 데이터 기간·실험 목록·비용·성과 승격 기준이 잠기기 전에는 새 성능 실험을 시작하지 않는다. 연구 승인과 실제 투자 정책 채택은 별도다.

### 결과를 보기 전에 잠글 항목

1. 시장·종목군·세션·데이터 manifest/hash와 과거 종목군 사용 여부.
2. 예측 목표: 후보의 20거래일 상대 성과와 다음 세션 가격/조건부 결과를 별도 실험으로 분리.
3. 학습/검증/시험 시작·종료 시각. 이미 연구자가 본 기간은 개발·진단용으로만 표기.
4. 특징 목록, 모델·하이퍼파라미터 시도 횟수, 결측 처리, 확률 보정 방법.
5. 주문 종류, 진입 이후 결과 라벨, 동일 봉 내 순서 불명 처리, 비용·슬리피지·부분 체결.
6. 비교 기준선, 1차 지표, 블록 재표본화 방법과 불확실성 평가, 다중 실험 선택 처리.
7. 수익성보다 위험 감소가 목적인 기능이면 사전에 그 목적과 수익 포기 허용 범위를 별도 명시.

초기 모델군은 M0(기존/단순 기준선), M1(단순 통계), M2(LightGBM) 범위에서 한정한다. 입력 감사가 통과하지 못하면 M2로 우회하지 않는다. 2026-09-21 이후 자료도 프로토콜 고정 전에 관찰·수정에 사용하면 미사용 시험 구간이 아니다. 진정한 최종 시험은 프로토콜 lock 시점 이후 또는 접근 이력이 통제된 자료로 정한다.

### 필수 기술 합격선

- 미래 정보, 생성 전 체결, 계좌 초과 매도, 현금 초과 사용, 사용자 간 데이터 누출: **0건**.
- 핵심 정보 시각과 가격 조정 방식이 UNKNOWN이면 관련 결과에 실행 가능 가격·수량을 표시하지 않는다.
- 5주 보유에서 3주 익절·1주 축소 후 청산 수량은 1주. 체결 순서를 바꿔도 잔여량 제약을 만족한다.
- 일봉의 고가·저가 도달만 보고 유리한 체결 순서를 택하면 실패. 분봉도 동일 봉 내 순서 불명확성을 처리해야 한다.
- 이전 세션의 종가와 현재 세션의 실시간 가격을 같은 기준가격으로 혼합하면 실패.
- 잘못된 통화·분할 계수·시각·중복 데이터에 정상 결과를 반환하면 실패.

### 성능 합격선의 형태

예측은 기준선 대비 분위수 손실/확률 점수가 개선되는지, 계획은 동일 비용·자본·위험 제약 아래 비용 후 효용이 개선되는지 평가한다. 날짜 블록 단위 불확실성을 보고하며 효과가 불명확하면 '미입증'이다. 시장·세션·국면별 결과와 거래 수를 함께 보고한다. 보편적인 승률 60% 같은 임의 목표는 사용하지 않는다.

구체적인 효과 크기·위험 허용선·표본 수·기간은 아직 확정하지 않았다. 이 값이 없는데 검증 기준이 완전히 확정됐다고 보고하지 않는다. 차후 데이터 커버리지 확인 후 첫 성능 실험 전에 고정한다.

- 입력: 위 계약에 맞춘 synthetic manifest/행, 기존 캐시의 읽기 전용 어댑터. 실제 API 키·계좌 데이터 없음.
- 출력: dataset별 PASS/WARN/BLOCKED, reasonCode, 근거 필드. 합격되지 않은 자료를 정제 명목으로 임의 수정하지 않음.
- 검사: `availableAt > cutoffAt`, 불명 시각/조정, 세션 부재, 중복/잘못된 OHLC, 통화 불일치, 필요 PIT 유니버스 부재.
- 기대 결과: 합성 정상·오류 케이스가 모두 기대 상태로 판정되고, 기존 일봉 자료는 분봉 요구를 통과하지 못함.
- 금지: 네트워크, 의존성 설치, 모델 학습, 전략 변경, 주문 실행, 커밋/푸시.

### Antigravity: 독립 검증

Claude 산출물이 생긴 뒤 검사기를 읽기 전용으로 검사한다. 미래 공시·정정값·DST·분할·동일 봉 양방향 체결·주문 잔여량 시나리오 중 검사기 범위와 계획 엔진 범위를 구별해 누락을 보고한다. 검사기가 가격 체결/주문 코어를 구현하지 않았는데 해당 기능까지 테스트 통과라고 표현하면 결함으로 지적한다. 이번 단계에는 UI 변경이 없어 UI 워커를 별도로 띄우지 않았다.

### Codex: 통합 관문

파일 허용 범위·기존 테스트와의 충돌·결과 증거를 확인하고 다음 데이터 실측 범위를 결정한다. 데이터 감사용 코드와 운영 주문 코드를 연결하지 않는다. 실거래 플래그·동의·예약을 변경하지 않는다.

## 9. 현재 남은 결정과 제한

현재 저장소에는 `TossOrderSubmissionProvider`, `ORDER_SUBMISSION`, 기본 false인 `live-enabled` 설정이 존재한다. 일부 문서는 여전히 자동 주문 미구현이라고 적혀 있어 문서 간 차이가 있다. 실제 로컬 설정과 사용자 동의는 읽지 않았으므로 실거래가 켜졌는지 단정하지 않는다. 이번 설계와 후속 검증은 그 실행 경로와 분리한다.

이번 감사는 완료됐지만 실제 데이터 취득·정규화·모델 검증은 미완료다. 권한 검토 서비스 복구를 확인하고 검사기 구현을 별도 Orca 작업 공간 `session-engine-data-preflight`(로컬, 이후 삭제됨)에서 시작했다. 원본 체크아웃과 운영 설정은 수정하지 않았다.
