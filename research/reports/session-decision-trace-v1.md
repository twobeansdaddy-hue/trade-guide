# 세션 가이드 입력·포트폴리오 추적 계약 v1

성격: 복구된 연구 저장소의 오프라인 **선언 검증기**. 현재 운영 DB에 실제 입력 추적 로그를 저장하는 기능은 아니다. 투자 전략 채택, 가격·수량 추천, 체결·수익률 검증과도 구분한다.

## 판정 대상

`decision_trace.validate(dataset, trace)`는 기존 시점 재생 검사에 더해 다음을 검사한다.

- 판단의 `modelInputIds`와 제출한 `features[].featureId`가 정확히 같은 집합인지. OHLC 참조는 `barIndices`와 `MARKET_BAR` 기능의 `barIndex` 집합이 같아야 한다.
- 가격 봉은 데이터셋의 실제 행 내용 해시와 수신·봉 종료 시각이 일치하는지. 기본적·거시·심리 지표는 원본 관측 시각(`sourceEventAt`), 이용 가능 시각(`availableAt`), 빈티지(`vintageAt`), 출처, 변환 버전, 내용 해시가 있는지. 기술 지표는 선행 입력(`dependsOn`)과 버전을 갖고, 입력보다 먼저 이용 가능했다고 주장하지 않는지.
- 포트폴리오 스냅샷은 상태의 기준 시각(`effectiveAt`), 캡처 시각(`capturedAt`), 기업행사 반영 기준 시각, 출처와 내용 해시를 갖고, 캡처 시각이 판단 시각 이전인지. 상태에는 보유 종목, 통화별 현금, 예약 주문 목록이 있어야 한다.
- 출처나 시각·해시가 누락되거나 미래라면 BLOCKED. 예제는 `SYN-*` 합성 값만 사용한다.

`contentSha256`은 정렬 키·공백 없는 JSON 직렬화(`sort_keys=true`, `separators=(",", ":")`, ASCII 이스케이프, NaN 불허)의 SHA-256이다. **내용 변경 감지용이며 인증 서명이 아니다.** 출처·시각 메타데이터는 이 내용 해시만으로 보호되지 않는다.

## 운영 코드 대조와 남은 연결점

- 현재 `PremarketGuideService`는 `PremarketGuideSnapshot`에 결과·`generatedAt`·선택한 시세 제공자를 저장한다. 각 지표/봉의 수신 시각·변환 버전·사용한 포트폴리오 스냅샷 ID는 저장하지 않는다.
- `PortfolioBrokerHoldingSnapshot`은 계좌별 보유 종목과 `syncedAt`을 저장하지만, 가이드가 실제 사용한 현금·예약 주문·전체 계좌 상태를 고정한 스냅샷은 아니다. 기존 보유 원장과 증권사 보유 스냅샷을 혼동하면 안 된다.
- 위 두 엔티티의 시각은 `LocalDateTime`이다. 시장/서버 시간대를 외부에서 추측해 UTC로 바꾸지 않는다. 운영 연결 전에 UTC `Instant`와 출처 시간대 규칙을 명시하는 데이터 모델 검토가 필요하다.
- 다음 운영 구현에서는 가이드 생성 트랜잭션 안에서 **실제 읽은 입력의 식별자와 해당 응답의 수신 시각**, 포트폴리오 상태 스냅샷의 원천·생성 시각·내용을 고정해야 한다. 현금·예약 주문이 확정되지 않았다면 `확인 불가`로 기록하고 수량 가이드 승격을 차단한다. 사용자 인증·계좌 분리·민감 정보 접근 제어도 이 설계의 전제다.

## 통과의 한계

검사기는 입력 목록과 시각이 **자기 선언대로 서로 맞는지**만 확인한다. 모델이 실제로 모든 입력을 신고했는지, 출처 기록이 진짜인지, 스냅샷이 실제 계좌와 맞는지, 내용 해시를 누가 다시 계산했는지는 독립 증명하지 못한다. 실제 데이터 확보와 운영 계보 기록은 아직 미구현이다. 현재 캐시에 없는 과거 수신 시각을 만들어 넣어서는 안 된다.

검증: 합성 입력 기준 데이터·수집·재생·추적 테스트 **124개 통과**. 계산 코어 테스트 **48개 통과**. 실제 시장 백테스트·체결 시뮬레이션·수익성 검증은 수행하지 않았다.
