# 전략 엔진 운영 정책

## 목적과 범위

Trade Guide는 투자 수익을 보장하거나 주문을 자동 실행하지 않는다. 이 문서는 리서치 결과를 전략 가이드와 사용자가 검토하는 예약 주문 계획으로 전환할 때 적용하는 기준이다.

## 의사결정 상태 분류

프로젝트에서 언급되는 투자 기법과 기능은 아래 상태를 명시적으로 구분한다.

| 상태 | 의미 | 현재 예시 |
| --- | --- | --- |
| 확정 요구사항 | 사용자가 구현 목표로 합의한 기능 또는 제약 | 미국 주식 대상, 보유 종목 가이드, 신규 후보 발굴, 장 시작 전 주문 계획 제시, 자동 주문 미실행 |
| 검증 중 가설 | 리서치 또는 백테스트 결과가 있으나 구현과 추가 검증이 남은 전략 | Track A/B 구분, SOXL 주봉 10/40 이동평균 가이드 |
| 학습/조사 후보 | 대화나 자료에서 언급됐지만 채택 여부를 결정하지 않은 기법 | 3분할 매도, RSI, MACD, 특정 손절 방식 |

학습/조사 후보는 언급만으로 전략 설정이나 코드에 반영하지 않는다. 채택하려면 리서치 근거, 실행 가능한 규칙, 검증 계획, 사용자의 명시적 결정을 거친다.

## 정보의 세 계층

```text
research/data/strategies.json
-> 리서치 근거와 전략 후보

실행 전략 설정
-> 기간, 조건, 수량 비율, 손절 규칙이 구조화된 활성 규칙

StrategyDecision / TradePlan
-> 특정 시점의 가이드와 사용자가 검토할 주문 계획
```

`strategies.json`의 자연어 신호와 리서치 결론은 엔진이 직접 실행하지 않는다. 활성 전략은 별도 설정과 테스트를 거쳐야 하며, 결과에는 사용한 전략 ID와 버전을 남긴다.

## 공통 가이드 원칙

- 결과에는 기준 시각, 가격 데이터 기준일, 전략 ID, 전략 버전, 신뢰도와 한계를 포함한다.
- 행동은 `BUY`, `HOLD`, `REDUCE`, `SELL`, `WATCH`처럼 구분한다. 기존 학습용 `TradeAction`과 전략 행동은 별도 모델로 관리한다.
- 가격 하나만으로 판단하지 않는다. 현재가, 목표 또는 지정가, 손절가, 확인 조건, 관련 지표값을 함께 제시한다.
- 확정된 봉 데이터만 전략 판단에 사용한다. 장전 가이드는 마지막으로 확정된 일봉 또는 주봉을 기준으로 한다.
- 모든 결과는 의사결정 지원 정보이며, 사용자가 최종 판단하고 증권사 주문을 등록한다.

## Track A: 레버리지 또는 고변동성 자산

- 초기 대상은 명시적으로 등록한 종목만 사용한다. 자동 분류는 베타 또는 ATR 기준이 검증된 뒤에 도입한다.
- SOXL의 첫 구현 후보는 주봉 10/40 이동평균 크로스오버다. 일봉 50/200 이동평균으로 임의 대체하지 않는다.
- 주봉 신호는 금요일 미국 장 마감 후 확정되며, 다음 거래일 장 시작 전 가이드에 반영한다.
- 매수 또는 매도 신호에는 포지션 비율, 손절가 계산식, 최대 비중, 유효 기간을 명시해야 한다.
- 분할 매도(예: 3분할)는 검토 가능한 후보 기법일 뿐 현재 채택된 기본 전략이 아니다. 향후 적용하려면 각 단계의 비율, 지정가 또는 조건, 잔여 수량 처리 규칙과 백테스트 근거를 별도로 정의한다.

## Track B: 일반 주식 신규 후보와 보유 종목

- 초기 후보 유니버스는 S&P 500으로 제한한다. 레버리지 ETF와 신규 후보 스크리닝을 혼합하지 않는다.
- 초기 필터는 `PEG > 0 && PEG < 1` 및 `현재가 > 50일 SMA`를 후보 발굴 조건으로만 사용한다. 이는 자동 매수 신호가 아니다.
- 후보 결과의 기본 행동은 `CANDIDATE` 또는 `WATCH`다. 매수 가이드가 되려면 가격 기준, 무효화 가격, 데이터 기준일과 위험 요인이 추가돼야 한다.
- PEG/PER, 실적 발표일, 현재가, 보도자료의 수집 시각과 출처를 결과에 표시한다. 결측치, 적자, 실적 발표 임박 종목은 경고 또는 제외한다.
- 보도자료와 뉴스는 매수 신호가 아니라 근거 설명과 위험 이벤트 확인에 사용한다. 기업 IR, SEC 공시, 실적 발표처럼 1차 자료를 우선한다.

## 예약 주문 계획 정책

- `StrategyDecision`은 판단이고, `TradePlan`은 사용자가 검토하는 주문 초안이다. 두 객체를 분리한다.
- 주문 초안에는 종목, 매수/매도 수량 또는 비율, 주문 유형, 지정가, 손절 발동가, 유효 기간을 포함한다.
- 익절 주문과 손절 주문을 동시에 제시할 경우 증권사의 OCO 또는 브래킷 주문 지원 여부를 확인한다. 지원되지 않으면 초과 매도 가능성을 경고하고 자동 주문 연동을 금지한다.
- 초기 토스증권 연동은 계좌/보유 종목 조회와 주문 초안 확인까지만 허용한다. 주문 전송 자동화는 백테스트와 모의 운영 결과를 검토한 뒤 별도 결정한다.

## 검증과 활성화 조건

- 새 전략은 단위 테스트, 과거 데이터 백테스트, 수수료/스프레드/슬리피지 가정, 데이터 조정 기준을 문서화한다.
- 학습 구간과 검증 구간을 분리하고, 가능한 경우 워크포워드 검증을 수행한다.
- 백테스트 표본 수, 기간, 생존 편향, 과최적화 가능성을 `confidence`와 `caveats`로 기록한다.
- 실제 사용 전에는 가상 주문 계획과 사후 결과 기록을 누적한다. 기대와 다른 결과는 전략 버전을 올리고 원인을 기록한다.

## 현재 구현 우선순위

1. 주봉 캔들 조회 지원
2. Track A 자산 프로필과 주봉 10/40 이동평균 전략
3. 전략 판단과 주문 초안 모델 분리
4. Track B용 펀더멘털/기업 이벤트 데이터 공급자
5. S&P 500 후보 스크리닝과 결과 추적

## 전략 채택 상태

- 사용자 대화에서 언급된 기법은 학습 질문 또는 조사 후보일 수 있으며, 언급만으로 활성 전략으로 채택하지 않는다.
- 활성 전략은 리서치 근거, 실행 가능한 규칙, 테스트와 검증 계획, 사용자의 명시적 채택을 모두 갖춘 경우에만 추가한다.
- 현재 첫 구현 후보는 주봉 10/40 이동평균을 사용하는 SOXL Track A 가이드다. 이 또한 구현과 검증 전에는 가설 단계로 취급한다.
